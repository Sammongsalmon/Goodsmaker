# 요구사항 회고와 새 프로젝트 기본 사양

이 문서는 굿즈 메이커가 초기 아이디어에서 현재 기능으로 발전하는 동안 **처음에는 빠졌고, 실제 사용 중 문제를 확인한 뒤 추가된 요구사항**을 정리한다. 미래 프로젝트에서는 아래 항목을 “나중에 넣을 옵션”이 아니라, 해당 유형의 웹이라면 처음부터 고려할 기본 사양으로 사용한다.

---

## 1. 제품 정체성과 화면 디자인

### 뒤늦게 조정된 항목

- 서비스 이름이 기능 확장에 따라 너무 좁아져 제목을 다시 변경함
- 제목 문자열 뒤의 이모지와 상단 아이콘 이모지를 분리함
- 강한 파란색이 눈에 피로해 저채도 하늘색으로 조정함
- 투명 체크무늬까지 테마색을 타면서 이미지 색 판별이 어려워 중립 회색으로 되돌림
- 자동 샘플 이미지가 실제 작업과 혼동되어 제거함
- 같은 주제의 옵션이 중첩 카드로 들어가 화면이 복잡해짐
- 이미 모드가 분명한데 라벨에 `유테/무테`가 반복되어 제거함
- 설명이 기술 중심이라 결과 중심 문장으로 수정함

### 새 프로젝트 기본 사양

- 서비스명은 향후 기능 확장을 고려해 특정 출력물 하나에 과도하게 종속하지 않는다.
- `<title>`, 화면 헤딩, 앱 아이콘을 별도 필드로 관리한다.
- 작업 배경은 색 판단을 방해하지 않는 회색 체크무늬를 기본으로 한다.
- 테마색은 저채도와 충분한 명도 대비를 사용한다.
- 첫 실행 샘플은 opt-in으로만 제공한다.
- 하나의 개념은 하나의 카드에 평평하게 배치한다.
- 라벨은 현재 화면 문맥을 반복하지 않는다.
- 도움말은 “이 값을 올리면 결과가 어떻게 달라지는가”를 설명한다.

## 2. 대지, 개체 크기, 확대율

### 뒤늦게 조정된 항목

- 대지 크기와 그림 크기가 결합되어 대지가 바뀌면 도안이 밀림
- 실제 그림 크기와 대지 크기를 따로 확인할 수 없었음
- 가로·세로 값을 입력하면 확대율이 필요하고, 확대율을 입력하면 가로·세로가 자동 계산되어야 했음
- 대지 밖으로 도안·타공·여백이 나갈 때 경고가 필요했음
- 출력 크기에 비해 원본 해상도가 부족한지 PPI 경고가 필요했음

### 새 프로젝트 기본 사양

```ts
interface ArtboardState {
  width: number;
  height: number;
  unit: 'mm'|'px';
}

interface ContentSizeState {
  width: number;
  height: number;
  scalePercent: number;
  aspectLocked: boolean;
  referencePpi: number;
}
```

- 대지와 콘텐츠 크기는 독립 상태로 둔다.
- `가로/세로 → 확대율`, `확대율 → 가로/세로` 변환을 양방향 제공한다.
- 100% 확대율의 기준을 명시한다. 예: 원본 픽셀을 300 ppi로 인쇄했을 때의 크기.
- 대지에 자동 맞춤은 명시적 버튼으로 제공하고 자동으로 크기를 바꾸지 않는다.
- 콘텐츠, 효과, 칼선, 타공을 포함한 최종 bounds를 기준으로 대지 이탈을 검사한다.
- PPI는 실제 배치된 크기로 계산한다.

## 3. 숫자 입력과 컬러피커

### 뒤늦게 조정된 항목

- 숫자만 입력하기 불편해 슬라이더가 추가됨
- 슬라이더가 항상 보이면 화면이 길어져 포커스 시에만 표시하도록 바꿈
- 위치, 크기, 회전 등 일부 값에만 슬라이더가 있어 조작 방식이 불일치함
- 기본 컬러피커가 모바일에서 비직관적인 별도 화면으로 열림
- 색 슬라이더가 검정→청록 진행 바로 보여 실제 이동할 색을 알 수 없었음
- 알파가 필요한 배경/효과에 투명도 선택이 빠짐

### 새 프로젝트 기본 사양

- 모든 연속 숫자 입력은 동일한 `NumericField`를 사용한다.
- 포커스/키보드 편집 중에만 슬라이더를 표시한다.
- 슬라이더 thumb는 흰 원, track은 실제 값의 의미를 보여준다.
- 색상은 자체 팝오버 피커를 사용한다.
- Hue는 무지개, alpha는 현재 색→투명 그라데이션으로 표시한다.
- HEX 8자리와 불투명도를 지원한다.
- color input의 native dialog만 유일한 편집 방법으로 사용하지 않는다.

## 4. 모바일과 데스크톱 조작

### 뒤늦게 조정된 항목

- 모바일에서 이동은 되지만 회전·크기 조절이 되지 않음
- 터치 스크롤과 캔버스 드래그가 충돌함
- 클릭 선택은 안 되고 드래그 선택만 되는 좌표 오류가 생김
- 더블클릭 그룹 내부 편집과 모바일 더블탭의 대응이 필요했음

### 새 프로젝트 기본 사양

- MouseEvent/TouchEvent 별도 구현 대신 Pointer Events를 쓴다.
- `pointerdown`에서 pointer capture를 사용한다.
- 클릭/드래그 구분 거리는 CSS px로 판단한다.
- 실제 좌표는 canvas rect와 내부 픽셀 크기를 이용해 변환한다.
- 이동, 모서리 크기 조절, 회전 핸들을 모바일에서도 충분히 큰 hit area로 만든다.
- 캔버스 편집 영역만 `touch-action: none`, 페이지 스크롤 영역은 유지한다.
- 더블탭은 동일 item ID, 시간, 이동 거리 조건을 모두 검사한다.

## 5. 선택, 다중 선택, 그룹, 내부 편집

### 뒤늦게 조정된 항목

- 단일 선택만 있던 상태에서 다중 선택이 추가됨
- 클릭 다중 선택과 빈 영역 드래그 선택이 모두 필요했음
- 선택 해제 규칙이 명확하지 않아 여러 차례 조정됨
- 합친 칼선은 같이 움직여야 하지만 내부 개체만 따로 움직일 수도 있어야 했음
- 이미지 작업 탭에서도 그룹이 필요했음
- 그룹 외곽선이 겹친 이미지 사이로 침범하는 문제가 발생함
- 그룹과 별개로 서로 다른 업로드 이미지도 칼선 그룹으로 합쳐야 했음
- 겹친 이미지의 위아래 순서 정책이 필요했음

### 새 프로젝트 기본 사양

- 상태는 `selectedIds: string[]`로 시작한다. 단일 ID만 저장하지 않는다.
- `groupId`, `groupEditIds`, `activeGroupId`를 별도 관리한다.
- 빈 캔버스 클릭은 선택 해제, 다중 모드 클릭은 toggle, drag marquee는 교차 선택으로 규정한다.
- 그룹 단일 클릭은 그룹 전체, 더블클릭/더블탭은 내부 편집이다.
- 그룹 내부에서 여러 개체를 다시 선택해 함께 움직일 수 있다.
- 그룹 효과는 개별 효과 합성이 아니라 union alpha 기준이다.
- 그룹 생성 시 z-order 정책을 사용자에게 선택시킨다.
- 그룹화/해제/내부 이동은 실행취소와 저장 복원 대상이다.

## 6. 실행취소, 재실행, 작업 복원

### 뒤늦게 조정된 항목

- 새로고침 시 모든 편집이 사라짐
- 나중에 IndexedDB를 붙이며 이전 단일 타공 구조를 배열로 마이그레이션해야 했음
- 모든 탭에 실행취소/재실행을 추가하면서 이벤트를 다시 감싸야 했음
- 새로고침 후 작업은 복원되지만 history는 별도 정책이 필요했음

### 새 프로젝트 기본 사양

- 첫 버전부터 schema version을 둔다.
- 원본 Blob과 문서 JSON을 분리한다.
- 이미지 Blob은 ID 참조로 history와 snapshot 복사를 줄인다.
- drag/slider의 연속 변화는 pointerup/commit 한 번으로 history에 넣는다.
- 이전 schema migration을 독립 함수로 관리한다.
- 복원 실패 시 빈 캔버스가 아니라 대지와 가능한 원본을 먼저 표시한다.
- 저장 위치가 same-origin 브라우저 저장소라는 점을 UI/README에 알린다.

## 7. 이미지 업로드와 알파 처리

### 뒤늦게 조정된 항목

- 꾸밀 개체와 패턴 이미지의 투명 여백 때문에 이동 중심과 크기가 어긋남
- 작은 AA 픽셀이 외곽선 스파이크를 만듦
- `0<alpha<255`를 전부 실제 반투명으로 오인함
- 파일 업로드 오류나 이전 저장 데이터 오류가 나면 대지까지 안 보이는 문제가 생김

### 새 프로젝트 기본 사양

- 모든 독립 개체는 alpha bounding box로 trim한다.
- 원본 픽셀은 보존하고 분석용 안정화 마스크를 따로 만든다.
- 작은 성분 제거는 실제 mm, 면적, 폭, 본체 접촉 길이를 함께 사용한다.
- 실제 반투명 면은 면적·두께·침식 core로 판정한다.
- 업로드 즉시 원본 preview를 먼저 표시하고 분석은 비동기로 진행한다.
- 파일을 같은 이름으로 다시 선택해도 input value를 초기화해 재업로드 가능하게 한다.

---

## 8. 칼선 곡선과 안정화

### 뒤늦게 조정된 항목

- contour 점을 줄이자 다각형이 됨
- smoothing을 올리자 전체 칼선이 변형됨
- 밑바닥 둥글기 슬라이더가 캐릭터 전체 외곽에 영향을 줌
- 작은 픽셀로 스파이크 발생
- 칼선이 대지 가장자리로 늘어나 붙음
- 좁은 홈 자동 연결이 밑받침의 의도적 빈 공간까지 메움

### 새 프로젝트 기본 사양

- 곡선 단순화는 점을 직선으로 잇는 작업이 아니라 adaptive Bézier fitting이다.
- smoothing 단위는 출력 mm 기준이다.
- 특수 구조물(밑받침, 고리)은 별도 geometry로 생성해 union한다.
- 국소 둥글기 값은 해당 구조물의 corner radius만 변경한다.
- 모든 외곽 연산은 padding이 있는 임시 마스크에서 수행한다.
- 보정 결과가 작업 마스크 경계에 닿으면 오검출로 폐기한다.
- 좁은 홈 연결은 원본 도안 외곽에 먼저 적용하고, 이후 추가된 의도적 빈 공간은 제외한다.

---

## 9. 재단여백/색상 확장

### 뒤늦게 조정된 항목

- 경계 1 px 샘플 때문에 AA 색과 엉뚱한 색이 확장됨
- 샘플 깊이를 늘리자 서로 다른 색이 섞여 블러처럼 됨
- 단색을 보존하려다 그라데이션이 사라짐
- 그라데이션을 보존하려다 단색이 줄무늬처럼 됨
- 원본과 확장 사이에 투명 실선이 남음
- 외부 타공 투명 고리 밖으로 색이 번짐
- 팔 색 대신 머리카락 색이 삼각형으로 침범함

### 새 프로젝트 기본 사양

- 한 픽셀 nearest color나 전체 평균 하나로 처리하지 않는다.
- 경계 안쪽 여러 깊이의 샘플과 connected region을 사용한다.
- flat/gradient/texture를 지역별로 분류한다.
- flat은 대표색 고정, gradient는 color field 외삽, texture는 edge-aware propagation을 사용한다.
- 서로 다른 region label 사이에서는 평균하지 않는다.
- 외부 타공 고리와 빈 공간은 propagation barrier로 처리한다.
- 확장 결과를 안쪽으로 2 px 겹치고 원본을 마지막에 재합성한다.
- AA는 최종 바깥 coverage에만 적용한다.

---

## 10. 화이트 레이어

### 뒤늦게 조정된 항목

- 반투명 픽셀 제외 화이트가 외곽 AA까지 제외함
- 실제 반투명 면이 없는 이미지에도 화이트 옵션 두 개가 표시되어 UI가 복잡함

### 새 프로젝트 기본 사양

- 실제 반투명 영역 분석을 먼저 수행한다.
- 감지되지 않으면 `화이트` 하나만 제공한다.
- 감지되면 `실제 반투명 면 제외`와 `전체` 두 레이어를 제공한다.
- 스티커가 겹칠 때 위쪽 이미지의 반투명 영역 아래에 아래 개체 화이트가 남지 않도록 최종 compositing 관계를 고려한다.

## 11. 밑받침

### 뒤늦게 조정된 항목

- 무테와 유테에서 같은 밑받침 규칙을 쓰기 어려움
- 빈 공간 유지/색상 채우기 두 모드가 필요함
- 전체 폭과 하단 유사색 범위 두 가지 가로 기준이 필요함
- 기울어진 바닥을 수평으로 자를지, 얼마나 위로 올릴지 옵션이 필요함
- 밑받침 옆으로 투명 픽셀이 튀어나옴
- 곡률 조정이 밑받침 자체에 적용되지 않거나 전체 도안에 영향을 줌

### 새 프로젝트 기본 사양

- 무테/유테 전략을 분리한다.
- 밑받침 shape와 원본 shape를 별도 생성한다.
- 빈 공간 유지 시 해당 공간과 외부 방향을 확장 금지 영역으로 기록한다.
- 가로 범위 전략: `하단 유사색 성분`, `도안 전체 폭`.
- 수평화 전략: `기울기 유지`, `높은 쪽 기준 crop`, `추가 올림 거리`.
- corner radius는 밑받침 외곽과 접합부에만 적용한다.

---

## 12. 타공

### 뒤늦게 조정된 항목

- 단일 타공에서 여러 타공 배열로 확장
- 내부/외부 타공 동작이 달라야 함
- 타공 위치 최종 확정 전 재연산이 너무 느림
- 다시 만들기 후 편집 가이드가 계속 보여 결과 확인이 어려움
- 클릭 선택 토글과 다중 타공 선택이 필요함
- 중앙 정렬, 외부 타공과 그림 사이 간격 커스텀이 필요함
- 외부 타공의 투명 고리를 색상 확장에서도 투명 픽셀처럼 처리해야 함

### 새 프로젝트 기본 사양

- 타공은 `Hole[]`로 시작한다.
- 각 타공에 draft/applied 위치와 치수를 둔다.
- 이동 중 가이드만 변경, 명시적 rebuild 시 geometry 반영.
- rebuild 후 selection만 끄고 데이터는 유지.
- 내부 타공과 외부 타공은 전략을 분리한다.
- 중앙 정렬과 개별 간격 필드를 기본 제공한다.
- 외부 타공 투명 영역은 색상 전파의 barrier이며, 원본 이미지와 겹치면 이미지가 우선한다.

## 13. 스티커 개체 쪼개기와 칼선 합치기

### 뒤늦게 조정된 항목

- 처음에는 파생 칼선 사이 거리를 threshold로 사용해 의도와 다른 합치기가 생김
- 0 mm에서 완전히 떨어진 개체가 모두 분리되어야 했음
- threshold를 넘는 개체도 수동으로 합칠 수 있어야 했음
- 다중 선택 대상은 적용된 이미지가 아니라 쪼개기 미리보기 칼선이어야 했음
- 드래그 선택은 되는데 클릭 선택이 안 되는 버그가 있었음
- 분리된 개체를 각각 이동·회전·크기 조절할 필요가 있었음
- 이미 불러온 다른 이미지와 기존 그룹도 칼선 합치기 대상이어야 했음

### 새 프로젝트 기본 사양

- 0 mm 분리는 원본 alpha connected components.
- threshold merge는 원본 성분 경계 사이 거리.
- 자동 merge와 수동 merge 정보를 분리.
- split preview component에도 안정적인 ID를 부여.
- preview 선택은 click toggle과 marquee를 모두 지원.
- apply 시 각 component의 원본 crop/좌표를 유지한 독립 item 생성.
- 수동 merge는 모든 item/group을 받을 수 있게 일반화.

## 14. 자동 배치와 정렬

### 뒤늦게 조정된 항목

- 단순 중앙 정렬 외에 위/아래/좌/우 칼선 기준 정렬이 필요함
- 다중 선택 묶음의 상대 위치를 유지한 정렬이 필요함
- 스티커 칼선 사이 최소 간격을 자동으로 확보해야 함
- 자동 배치가 기존 배치를 완전히 망가뜨리지 않고 최소 이동이어야 함

### 새 프로젝트 기본 사양

- 정렬 기준을 이미지 box가 아니라 선택 가능한 geometry 기준으로 둔다.
- 그룹/다중 선택의 union bounds를 사용한다.
- 자동 배치는 충돌 쌍만 반복 완화하는 최소 이동 방식으로 구현한다.
- 대지 경계와 잠긴 개체를 제약으로 포함한다.
- 해결 불가능하면 남은 충돌 수와 원인을 알려준다.

## 15. 배경과 패턴

### 뒤늦게 조정된 항목

- 단색뿐 아니라 그라데이션, 이미지, 반복 패턴, 투명 배경이 필요함
- 배경 이미지에 fill/contain/stretch/custom, 확대율, X/Y, 회전이 필요함
- 패턴에 사각 그리드/사선 그리드/땡땡이/줄무늬/별/하트/사각별/팔각별이 추가됨
- 선 패턴에 실선/점선과 선 굵기가 필요함
- 입자 패턴에 크기, 간격, 사각/사선 배열이 필요함
- 크기 랜덤, 위치 랜덤, 분산, 밀도, 회전 랜덤이 필요함
- 여러 이미지를 패턴으로 쓸 때 모두 사용하고 투명 여백을 잘라야 했음
- 홀수 이미지 수에서도 자연스럽게 섞여야 했음
- 바로 위아래 행에서 같은 순서가 반복되지 않게 서로소 행 이동이 필요함
- 랜덤 순서 옵션도 필요함
- 패턴 자체의 배경도 그라데이션이 필요함

### 새 프로젝트 기본 사양

- background와 pattern을 독립 모델로 설계한다.
- 선 패턴과 입자 패턴의 옵션 UI를 분리한다.
- 입자 템플릿은 path generator registry로 확장 가능하게 만든다.
- 모든 업로드 패턴 이미지를 alpha trim한다.
- 배열 순서는 balanced coprime shift와 seeded random을 제공한다.
- size/position/rotation randomness는 같은 seed에서 고정된다.
- density와 dispersion의 의미를 분리한다.
- 패턴 배경은 transparent/solid/gradient를 지원한다.

## 16. 일반 이미지 메이커와 제작 모드 분리

### 뒤늦게 조정된 항목

- 외곽선/배경 탭의 목적은 일반 이미지 제작인데 칼선·화이트 UI가 남아 있었음
- 일반 이미지 탭에는 PNG/JPG만 필요함
- 투명 배경과 흰 배경 PNG 선택이 필요함
- 개체 효과를 다른 개체에 일괄 적용할 버튼이 필요함
- 꾸밀 개체에도 투명 여백 자동 제거가 필요함
- 여러 개체를 그룹화해 겹친 이미지를 한 그림으로 인식한 외곽선이 필요함

### 새 프로젝트 기본 사양

- production 기능과 general image maker를 mode capability로 분리한다.
- 일반 이미지 모드에는 칼선/화이트/AI/SVG 제작 옵션을 노출하지 않는다.
- 효과 복사/일괄 적용을 제공한다.
- 그룹 효과는 union alpha 기준으로 처리한다.
- PNG transparent/white, JPG opaque export 정책을 명확히 한다.

## 17. 내보내기와 호환성

### 뒤늦게 조정된 항목

- 체크한 출력물만 PNG로 합성 저장하는 기능이 필요함
- 파일명 입력과 기본 파일명 fallback이 필요함
- SVG가 Edge에서는 보이지만 Illustrator에서 연결 파일 누락으로 열리지 않음
- `.ai`가 네이티브 AI인지 PDF 호환인지 설명이 필요함
- 각 레이어를 내보내기에 포함할지 선택해야 했음

### 새 프로젝트 기본 사양

- 모든 렌더 레이어는 독립 노드로 유지한다.
- export layer checklist를 데이터 모델에 넣는다.
- filename sanitize와 extension normalization을 공통 함수로 만든다.
- SVG bitmap은 data URI로 파일 내부에 포함한다.
- `href`와 `xlink:href`, `xmlns:xlink`, SVG 1.1을 같이 제공한다.
- 브라우저, Illustrator, PDF viewer에서 재열기 테스트한다.
- PDF-compatible AI는 네이티브 AI가 아님을 명시한다.

## 18. 성능과 연산 시점

### 뒤늦게 확인된 항목

- GitHub Pages 대신 Railway로 옮기면 빨라질 것이라 기대했지만 연산이 브라우저에 있어 효과가 없음
- 타공 위치를 움직일 때마다 전체 칼선·색상 확장이 다시 계산되어 번거로움
- 스티커 대지 전체를 매번 계산해 느림
- random pattern이 렌더마다 달라지면 편집이 불가능함

### 새 프로젝트 기본 사양

- 어디에서 연산하는지 먼저 설명한다.
- draft/applied 상태를 둔다.
- pointermove에서는 transform preview만 변경한다.
- 계산 범위를 item 주변 ROI 또는 boundary band로 제한한다.
- generation token으로 오래된 비동기 결과를 폐기한다.
- deterministic seed를 사용한다.
- 필요하면 Worker/OffscreenCanvas로 이동한다.

- 여러 개체가 한 파일에 들어올 수 있는가?

### 배경/패턴

- 투명/단색/그라데이션/이미지/패턴 중 무엇을 지원하는가?
- 여러 패턴 이미지를 섞는가?
- 크기/위치/회전 랜덤과 seed 고정이 필요한가?
- 패턴 바탕색에도 alpha/gradient가 필요한가?

### 내보내기

- PNG/JPG/SVG/PDF/AI 중 무엇이 필요한가?
- 레이어별 선택 출력이 필요한가?
- Illustrator 호환이 완료 조건인가?
- 투명/흰 배경 선택과 파일명 입력이 필요한가?

- 홀, 밑받침, 좁은 홈 자동 연결이 필요한가?
- 단색/그라데이션 재단여백이 필요한가?
- 화이트 레이어의 반투명 정책은 무엇인가?

## 20. 미래 구현의 기본 결정

사용자가 별도 지시하지 않았고 프로젝트가 이미지 편집 성격이라면 다음을 기본값으로 제안한다.

- Pointer Events 기반 모바일/데스크톱 공통 조작
- 다중 선택 가능한 상태 모델
- 그룹 union-alpha 효과
- IndexedDB 자동 저장과 history
- 포커스 시 나타나는 numeric slider
- 자체 Hue/SV/alpha 컬러피커
- 투명 여백 자동 trim
- 결정적 랜덤 패턴
- 대지와 콘텐츠 크기 분리
- 미리보기와 export 렌더 파이프라인 통합
- SVG bitmap 임베드 호환 처리
- UI의 context-aware option disclosure

이 기본 결정을 기획서에 미리 적고 사용자가 필요 없는 항목만 빼는 방식이, 기능을 하나씩 뒤늦게 붙이는 방식보다 효율적이다.
